# Техническое описание логики (v2.2)

Подробное описание архитектуры и алгоритмов работы системы управления SSH-ключами с использованием UUID.

## 1. Конфигурационный файл

Файл настроек в формате JSON, располагается в одной директории со скриптом. Имя файла формируется динамически на основе имени самого скрипта: `{script_name}.cfg`.

### Структура полей
- `_comment`: Текстовое описание (игнорируется).
- `uuid`: Уникальный идентификатор экземпляра. Генерируется однократно при первом запуске (UUID4).
- `local_key_dir`: Локальный путь для хранения ключей. Если `null`, используется подпапка `ssh_keys`.
- `servers`: Список объектов серверов.

## 2. Жизненный цикл UUID

1. **Создание:** При отсутствии конфига создается шаблон с `uuid: null`.
2. **Инициализация:** При первом полноценном запуске скрипт генерирует UUID и сохраняет его обратно в файл.
3. **Использование:** UUID вшивается в комментарий публичного ключа при каждом деплое.

## 3. Формат комментария ключа

```
{username}@{host}:{server_name}:{uuid}
```
Такой формат обеспечивает уникальность и позволяет проводить селективную очистку старых доступов.

## 4. Алгоритм деплоя и очистки (connect_and_setup_ssh)

При установке нового ключа (когда вход выполнен по паролю) скрипт выполняет:

1. **Сбор данных:** Вычитывает текущий `authorized_keys` с сервера.
2. **Анализ:**
   - Строки, содержащие `{username}@{host}:{server_name}:`, считаются управляемыми этим скриптом.
   - **Случай А:** Совпадают и UUID, и сам публичный ключ. Это актуальный ключ, он оставляется.
   - **Случай Б:** Совпадает UUID, но контент ключа другой. Это устаревший ключ того же экземпляра (например, если локальные ключи были перегенерированы). Помечается как старый.
   - **Случай В:** UUID отличается. Это ключ другого экземпляра скрипта для этого же сервера. Помечается как старый.
3. **Очистка:**
   - Если найдены старые ключи (Случаи Б и В), выводится уведомление и запрос подтверждения `(y/n)`.
   - При подтверждении старые ключи удаляются из результирующего списка.
4. **Добавление:** В список добавляется текущий актуальный ключ (если его еще нет).
5. **Запись:** Выполняется полная перезапись файла через `cat >`.

## 5. Особенности Proxmox

Команда `cat >` прозрачно записывает данные в целевой файл, на который указывает символическая ссылка `authorized_keys`.

## 6. Безопасность

- Ключи без паттерна `server_name:uuid` никогда не удаляются.
- Удаление всегда требует подтверждения.
- Имя конфигурационного файла привязано к имени скрипта, что позволяет держать несколько независимых копий скрипта в одной папке с разными настройками.
