# Техническое описание логики скрипта

В данном документе приведено подробное описание внутренней архитектуры и алгоритмов работы `ssh_key_manager.py`.

## Архитектура скрипта

Скрипт разбит на логические блоки:
1.  **Блок констант:** Глобальные настройки (серверы, пути, таймауты).
2.  **Поддержка интерфейса:** Включение ANSI в Windows (`enable_windows_ansi`) и логгирование (`log`).
3.  **Связь с сервером:** Выполнение команд через SSH (`execute_remote_command`).
4.  **Основная логика:** Настройка доступа (`connect_and_setup_ssh`).
5.  **Оркестрация:** Цикл обработки в `main()`.

## Алгоритм подключения и настройки

Для каждого сервера в списке выполняется следующая последовательность действий:

1.  **Определение имени ключа:**
    - Используется `name` из конфига. Если его нет — `host` с заменой точек на подчёркивания.
2.  **Попытка входа по ключу:**
    - Если файл `id_rsa_{name}` существует, выполняется попытка подключения.
    - При успехе — переход к тестированию.
3.  **Аутентификация по паролю (Fallback):**
    - Если ключа нет или он не подошёл:
        - Пробуется пароль из конфига (если задан).
        - Если пароль не задан или неверен — запрашивается ввод в консоли.
4.  **Генерация ключей:**
    - Если вход выполнен по паролю, генерируется новая пара RSA 4096 бит.
    - Ключи сохраняются локально в формате OpenSSH.
5.  **Деплой на сервер:**
    - Проверяется существование `~/.ssh`. Если нет — создается с правами 700.
    - Проверяется существование `authorized_keys`. Если нет — создается с правами 600.
    - **Важно:** Если объекты уже существуют, `chmod` не вызывается (критично для Proxmox).
6.  **Проверка дубликатов:**
    - Содержимое `authorized_keys` вычитывается и сравнивается построчно с новым ключом в Python.
    - Ключ добавляется только если его еще нет в файле.

## Особенности Proxmox и кластерных ФС

В Proxmox `authorized_keys` часто является симлинком на `/etc/pve/priv/authorized_keys`.
- Прямая перезапись файла или изменение его прав (`chmod`) могут привести к ошибкам "Read-only file system" или нарушению работы кластера.
- Скрипт использует `cat >>`, что корректно обрабатывает симлинки, записывая данные в целевой файл.

## Обработка ошибок

- Скрипт использует блок `try...except` внутри цикла `main()`.
- Ошибка на одном сервере не прерывает обработку остальных.
- В конце работы выводится сводный отчет обо всех серверах, на которых возникли проблемы.

## Цветовое оформление

Используется стандарт ANSI. Префиксы помогают быстро определить статус операции:
- `[OK]` (Зеленый): Успешное завершение этапа.
- `[X]` (Красный): Ошибка.
- `[!]` (Желтый): Предупреждение или важное уведомление.
- `[i]` (Циан): Информационное сообщение.
- `[...]` (Синий): Процесс выполнения.

## Поддержка Windows

Для корректного отображения цветов в Windows CMD/PowerShell используется вызов `SetConsoleMode` через `ctypes` для включения флага `ENABLE_VIRTUAL_TERMINAL_PROCESSING`.
