# Техническое описание логики (v2.3)

## 1. Резервное копирование
Перед полной перезаписью файла `authorized_keys` на удаленном сервере, скрипт создает его резервную копию:
`cp authorized_keys authorized_keys.bak.YYYY-MM-DD_HH-MM-SS`
Это позволяет откатить изменения в случае непредвиденных ошибок.

## 2. Управление длиной ключа
- Глобальное значение по умолчанию: `3072` бит (оптимальный баланс между скоростью и безопасностью).
- Параметр `key_size` в конфигурации сервера позволяет задать индивидуальное значение (2048, 3072, 4096).
- При генерации ключа скрипт логирует фактический выбранный размер.

## 3. Режим проверки (--show)
Режим `--show` предназначен для аудита текущего состояния доступа без модификации файлов:
1. Скрипт подключается к серверам только по существующим локальным ключам.
2. Не запрашивается пароль и не генерируются новые ключи.
3. Выводится статус: "доступен по ключу", "аутентификация отклонена" или "ошибка подключения".

## 4. Конфигурация и UUID
- UUID генерируется сразу при создании шаблона конфига.
- Если в существующем конфиге значение `uuid` установлено в `null`, скрипт сгенерирует новый идентификатор. Это приводит к тому, что все ранее установленные ключи (с другим UUID) будут считаться устаревшими.

## 5. Формат комментария ключа
Остается неизменным: `{username}@{host}:{server_name}:{uuid}`.

## 6. Алгоритм деплоя
1. Аутентификация (ключ -> пароль -> ввод).
2. Анализ `authorized_keys` и выделение старых ключей.
3. Подтверждение удаления пользователем.
4. Создание бэкапа `cp`.
5. Запись нового содержимого `cat >`.
