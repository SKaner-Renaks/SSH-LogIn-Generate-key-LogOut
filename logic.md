# Техническое описание логики (v2.3)

Данный документ описывает внутреннее устройство и алгоритмы работы скрипта `ssh_key_manager.py`.

## 1. Архитектура
Скрипт построен по функциональному принципу. Перечень основных функций:
- `main()`: Точка входа, оркестрация процессов.
- `connect_and_setup_ssh()`: Основной процесс настройки доступа.
- `execute_remote_command()`: Выполнение SSH-команд.
- `log()`: Форматированный вывод.
- `enable_windows_ansi()`: Поддержка цветов в Windows.
- `test_connection()`: Верификация доступа.
- `disconnect_ssh()`: Завершение сессии.

## 2. main()
- **Загрузка конфига:** Динамическое определение пути `{script_name}.cfg`. Чтение JSON.
- **Определение путей:** Установка `local_key_dir` (по умолчанию `ssh_keys`).
- **UUID:** Проверка наличия и автоматическая генерация идентификатора экземпляра.
- **Цикл обработки:** Итерация по списку серверов с проверкой флага `enabled`.
- **Сводка:** Сбор результатов выполнения и вывод финального отчета.

## 3. connect_and_setup_ssh()
Полный алгоритм настройки:
1. **Проверка ключа:** Попытка входа по локальному RSA-ключу.
2. **Пароль:** При неудаче — вход по паролю (из конфига или ввод вручную).
3. **Генерация:** Создание новой пары ключей при необходимости.
4. **Деплой:** Развертывание публичного ключа на сервере.

## 4. Генерация ключей
- **Метод:** `paramiko.RSAKey.generate()`.
- **Длина:** Настраиваемая (2048, 3072, 4096 бит).
- **Формат:** Сохранение в формате OpenSSH (`write_private_key_file`).

## 5. Деплой ключа
- **Проверка окружения:** Убеждается в наличии `.ssh` (700) и `authorized_keys` (600).
- **Анализ строк:** Парсинг текущих ключей для поиска управляемых записей.
- **Очистка:** Удаление старых версий ключей этого экземпляра (по UUID).
- **Бэкап:** Создание резервной копии перед записью.
- **Запись:** Полная перезапись файла актуальным набором строк.

## 6. UUID и идентификация
- **Генерация:** UUID4 генерируется один раз и хранится в конфиге.
- **Комментарий:** Ключ идентифицируется по строке `user@host:server_name:uuid`.
- **Поиск:** Скрипт находит свои ключи на сервере даже при изменении их контента, если совпадает паттерн комментария.

## 7. execute_remote_command()
- Принимает команду и описание.
- Логирует команду (Bright Green).
- Выполняет через `exec_command`.
- Синхронизирует выполнение через `recv_exit_status()`.

## 8. log()
- Добавляет временную метку `[HH:MM:SS]`.
- Применяет цвета к префиксам (`[OK]`, `[X]`, `[!]`, `[i]`, `[...]`, `>>>`).
- Обеспечивает читаемость вывода в различных терминалах.

## 9. enable_windows_ansi()
- Активация обработки ANSI-последовательностей в Windows.
- Использует `ctypes` для установки `ENABLE_VIRTUAL_TERMINAL_PROCESSING` (0x0004).

## 10. test_connection()
- Выполняет команду `ls -la /` для подтверждения успешного входа по новому или существующему ключу.

## 11. disconnect_ssh()
- Корректное закрытие сессии SSH.
- Логирование завершения работы с сервером.

## 12. Режим --show
- Упрощенный цикл проверки доступности.
- Использует только существующие ключи.
- Не вносит изменений и не запрашивает пароли.

## 13. Бэкап
- Создание копии `authorized_keys` непосредственно перед перезаписью.
- Имя бэкапа содержит метку времени: `authorized_keys.bak.YYYY-MM-DD_HH-MM-SS`.

## 14. Обработка ошибок
- Локальная обработка `AuthenticationException` для переключения режимов входа.
- Глобальная обработка исключений в `main()` для обеспечения живучести цикла обработки списка серверов.
