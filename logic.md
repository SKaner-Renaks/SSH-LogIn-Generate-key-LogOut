# Техническое описание логики (v2.1)

Подробное описание архитектуры и алгоритмов работы системы управления SSH-ключами с использованием UUID.

## 1. Конфигурационный файл `ssh_manager.cfg`

Файл настроек в формате JSON, располагается в одной директории со скриптом.

### Структура полей
- `_comment`: Текстовое описание (игнорируется).
- `uuid`: Уникальный идентификатор экземпляра. Генерируется однократно при первом запуске (UUID4).
- `local_key_dir`: Локальный путь для хранения ключей. Если `null`, используется подпапка `ssh_keys`.
- `servers`: Список объектов серверов.

### Поля сервера
| Поле | Тип | Описание |
|---|---|---|
| `name` | string | Имя сервера для файлов и комментариев |
| `host` | string | IP или домен сервера |
| `enabled` | boolean | Если `false`, сервер пропускается при обработке |
| `username` | string | Логин SSH |
| `password` | string/null | Пароль (null = интерактивный ввод) |
| `remote_home` | string | Домашняя директория на сервере |

## 2. Жизненный цикл UUID

1. **Создание:** При отсутствии конфига создается шаблон с `uuid: null`.
2. **Инициализация:** При первом полноценном запуске скрипт генерирует UUID и сохраняет его обратно в файл.
3. **Использование:** UUID вшивается в комментарий публичного ключа при каждом деплое.
4. **Смысл:** Позволяет скрипту отличать "свои" ключи от "чужих" (созданных другими копиями скрипта или вручную).

## 3. Формат комментария ключа

```
{username}@{host}:{server_name}:{uuid}
```
Такой формат обеспечивает уникальность и позволяет проводить селективную очистку старых доступов.

## 4. Алгоритм деплоя и очистки (connect_and_setup_ssh)

При установке нового ключа (когда вход выполнен по паролю) скрипт выполняет:

1. **Сбор данных:** Вычитывает текущий `authorized_keys` с сервера.
2. **Анализ:**
   - Строки, содержащие `{username}@{host}:{server_name}:`, считаются управляемыми этим скриптом.
   - Если UUID в строке совпадает с текущим — это актуальный ключ.
   - Если UUID отличается — это старый ключ этого же экземпляра скрипта.
3. **Очистка:**
   - Если найдены старые ключи, выводится уведомление и запрос подтверждения `(y/n)`.
   - При подтверждении старые ключи удаляются из результирующего списка.
4. **Добавление:** В список добавляется текущий актуальный ключ.
5. **Запись:** Выполняется полная перезапись файла через `cat >`. Это гарантирует атомарность и чистоту файла.

## 5. Особенности Proxmox

Скрипт по-прежнему корректно работает с Proxmox, где `authorized_keys` может быть симлинком. Команда `cat >` прозрачно записывает данные в целевой файл, на который указывает ссылка.

## 6. Безопасность

- Ключи, не имеющие в комментарии связки `server_name:uuid`, скриптом никогда не удаляются.
- Удаление всегда требует интерактивного подтверждения пользователя.
- Приватные ключи сохраняются с правами `600`.
- Отключенные серверы (`enabled: false`) не обрабатываются, что предотвращает случайные изменения.
